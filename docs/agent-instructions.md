## Общение страницами (agent-ui)

С человеком агент говорит только страницами agent-ui. Текст в терминале — это
ссылка и одна строка сути, больше ничего.

| Что нужно человеку          | Чем ответить                                               |
| --------------------------- | ---------------------------------------------------------- |
| Короткий ответ              | заметка текстом → `publish.mjs`, в чат — строка и ссылка   |
| Ответ со структурой         | лист виджетов → `publish.mjs`, в чат — строка и ссылка     |
| Ход долгой работы           | лист `<slug>-progress`, публиковать на каждом этапе        |
| Вопрос, выбор, согласие     | экран вопроса → `ask.mjs`, ждать ответа, текстом не спрашивать |
| Команда agent-ui упала      | текст: причина из stderr; ссылку не выдумывать             |

Короткий ответ — заметка простым текстом, без JSON: так меньше токенов.
Первая строка — заголовок, строки с `- ` — список фактов, остальное — вывод.

```bash
node {{ROOT}}/scripts/publish.mjs - --id <slug> --tone good <<'EOF'
Тесты прошли
16 из 16.
- ветка main
- SHA fa521d7
EOF
```

`--tone` — `good`, `bad`, `warn` или `info`, можно не указывать. Лист JSON
пиши, только когда нужен другой виджет: таблица, шаги, шкала.

`slug` — по теме разговора: один вопрос, одна ветка работы — один `--id`.
Новая тема — новый `--id`. Повторная публикация с тем же `--id` заменяет
страницу; 20 прошлых версий лежат в `/a/<slug>/history`. Вывод держи под
`<slug>`, ход работы — под `<slug>-progress`: так ход не закрывает вывод.
Кнопка «История» слева сверху на листе показывает все листы и версии
текущего git-дерева. Дерево и ветку `publish.mjs` берёт из каталога запуска:
запускай его из рабочего дерева задачи.

### Как спросить человека

```bash
node {{ROOT}}/scripts/ask.mjs - <<'EOF'
{ "title": "Куда отправить MR?", "submit": "Ответить",
  "blocks": [
    { "kind": "text", "text": "Проверки прошли. Выбери целевую ветку." },
    { "kind": "choice", "id": "target", "label": "Ветка", "options": ["release", "main"] },
    { "kind": "input", "id": "note", "label": "Комментарий", "multiline": true } ] }
EOF
```

Блоки экрана: `text`, `table {columns, rows}`, `choice {id, label, options,
multi?}`, `checklist {id, label, items}`, `input {id, label, multiline?}`.
Команда сама откроет браузер, если страница agent-ui не открыта, и ждёт до
10 минут: запускай её с таймаутом инструмента 600000 мс. В stdout придёт
`{"status":"answered","answers":{...}}` или `{"status":"timeout"}`. Таймаут —
опубликуй лист «жду решения» с вопросом и остановись.

Вопрос средствами агента (AskUserQuestion, вопрос в чате) не задавай: человек
отвечает только на странице.

### Вопросы со страницы

На любом листе человек выделяет фразу, жмёт «Спросить агента» и пишет вопрос.
Лист опубликовала сессия Claude Code — на вопрос отвечает её форк, как `/btw`:
`claude -p --resume <сессия> --fork-session` с инструментами Read, Grep и Glob.
Ответ форка приходит в карточку на листе, основная сессия его не видит.

Лист опубликовал другой агент — вопрос ложится в очередь сервера. Тогда после
публикации листа запусти в фоне:

```bash
node {{ROOT}}/scripts/inbox.mjs --id <slug> --wait
```

В stdout придёт `{"questions":[{quote, question, context, version}]}`. Ответь
новой версией того же `--id` и снова запусти `inbox.mjs --wait`. Без `--wait`
команда сразу отдаёт очередь, пустую или нет.

### Как собрать

По умолчанию — **лист виджетов**: JSON-файл, сервер сам рисует его в стиле
чертежа (рамка, панели A, B, C…, штамп с названием). Свой HTML пишут, только
когда ни один виджет не подходит (интерактив, своя схема на SVG).

```json
{ "title": "2–6 слов", "summary": "1–2 фразы вывода",
  "meta": [["Ветка", "main"], ["SHA", "fa521d7"]],
  "panels": [{ "title": "Один вопрос", "caption": "необязательно", "span": 2,
               "widgets": [{ "kind": "stats", "items": [...] }] }] }
```

`span` — ширина панели из 4 колонок: 4 — во всю ширину, 2 — половина, 1 —
узкая справка.

Пределы листа: строка — до 4000 знаков и не пустая (кроме заголовка колонки
таблицы); панелей — до 26; строки `list` не повторяются; в строке таблицы
столько ячеек, сколько колонок. Лист длиннее 20 строк пиши файлом и публикуй
путь, а не heredoc. Полный пример со всеми виджетами:
`{{ROOT}}/examples/widgets.json`, вид —
<http://127.0.0.1:47700/a/widgets>.

### Какой виджет когда

| Вопрос читателя                     | Виджет      | Поля                                                        |
| ----------------------------------- | ----------- | ----------------------------------------------------------- |
| Сколько? Главное число              | `stats`     | `items[{label, value, unit?, delta?, tone?, note?}]`        |
| Укладываемся ли в предел?           | `gauge`     | `items[{label, value, max, limit?, unit?, note?}]`          |
| Что больше, что меньше?             | `bars`      | `unit?, items[{label, value, tone?}]`                       |
| Сравнить объекты по свойствам       | `table`     | `columns[string\|{title,mono,align}], rows[[cell]], note?`  |
| Из чего состоит целое?              | `tree`      | `root{label, tag?, note?, children[...]}`, до 4 уровней     |
| Что не так в этой строке/фразе?     | `annotated` | `label?, caption?, parts[string\|{text, note?, tone?}]`     |
| Что и когда случилось?              | `timeline`  | `items[{when, title, note?, tone?}]`                        |
| Где мы в процессе?                  | `steps`     | `items[{title, status: done\|active\|todo\|failed\|skipped, note?}]` |
| Прошло или нет? Итог проверок       | `verdicts`  | `items[{title, status: pass\|warn\|fail\|skip, evidence?}]`; итог по худшему сервер ставит сам |
| Какой вариант выбрать?              | `options`   | `items[{title, what, cost?, risk?, recommended?}]`, рекомендация — одна |
| Что сделать / перечень              | `list`      | `items[string], ordered?`                                   |
| Справка: параметры, окружение       | `keyvalue`  | `items[[ключ, значение]]`                                   |
| Вывод, риск, блокер                 | `callout`   | `tone?, title?, text`                                       |
| Что изменилось в коде?              | `diff`      | `file?, lines[«+…», «-…», «@@…», « …»]`                     |
| Что скопировать и запустить         | `code`      | `label?, text`                                              |
| Пояснение, которое не влезло в виджет | `text`    | `text, muted?`                                              |

Тона: `good` — норма, `bad` — сбой или нарушение, `warn` — риск, `info` —
справка, `neutral` — без оценки. Тон — это оценка, а не украшение: ставь его,
только когда он что-то значит. `gauge` сам краснеет выше `limit`.

Порядок листа: сначала вывод (`summary`, `stats` или `callout`), потом
доказательство (`table`, `gauge`, `bars`, `diff`), потом справка (`keyvalue`,
`code`). Одна панель — один вопрос. Схема или показатель идут раньше абзаца:
если мысль можно показать числом, шкалой, деревом или таблицей, абзац не нужен.

### Как писать текст

Пиши на 80% по ASD-STE100 (Simplified Technical English), по-русски:

- одна мысль в предложении; процедура — до 20 слов, описание — до 25;
- активный залог и повелительное наклонение: «Перезапусти сервер», а не
  «Сервер должен быть перезапущен»;
- одно слово — одно значение; термин не меняй синонимом посреди текста;
- без вводных, оценок и воды: факт, число, действие.

Сервер отклоняет лист, экран и HTML с нарушением: ответ 400 называет поле и
фразу. Он проверяет три правила: предложение до 25 слов, нет пассива вида
«был удалён», нет вводных и оценок («на самом деле», «очень»). Код, diff,
`mono`-ячейки и части `annotated` он не проверяет. Исправь фразу и опубликуй
снова.

### Как опубликовать

`node {{ROOT}}/scripts/publish.mjs <заметка.txt | лист.json | файл.html> --id <slug>`

Вместо файла можно `-` и содержимое через stdin: `{` в начале — лист JSON,
`<` — HTML, иначе — заметка.
Команда сама поднимет сервер на 127.0.0.1 и напечатает ссылку
`http://127.0.0.1:47700/a/<slug>`. В чате — одна строка сути и ссылка.

Любая страница — в стиле чертежа: рамка, линейки, штамп, панели A, B, C.
Лист виджетов и заметка получают этот стиль сами. Свой HTML собирай на той же
разметке: `<html lang="ru" data-kit="v6">`, `<title>` из двух–четырёх слов,
`<link rel="stylesheet" href="http://127.0.0.1:47700/kit.css">` и
`<link rel="stylesheet" href="http://127.0.0.1:47700/sheet.css">`, затем
`.frame` → `.sheet` → `header.stamp` → `.panels` → `section.panel span-N`.
Других внешних ресурсов нет. Разметку образца смотри в коде страницы
<http://127.0.0.1:47700/a/widgets/raw>.

Повторная публикация с тем же `--id` обновляет открытую страницу на лету: так
ведут живой отчёт по ходу долгой работы. `slug` — латиница в нижнем регистре,
цифры и дефис. Все страницы — <http://127.0.0.1:47700/a>.

Команда упала — прочитай stderr. Ошибка листа называет путь до поля
(`sheet.panels[1].widgets[0].items[2].max: …`): исправь поле и опубликуй снова.
Не вышло — ответь текстом с причиной; не выдавай ссылку, которую не получил.
В песочнице без доступа к 127.0.0.1 (Codex) попроси разрешение на сеть для этой
команды, а не переходи на текст молча.
